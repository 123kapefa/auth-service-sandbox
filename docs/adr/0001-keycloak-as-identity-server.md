# 0001. Keycloak — сервер входа платформы

**Статус:** Принято · **Дата:** 2026-10-05 · **Этапы:** 1–6б

## Контекст

Боевой сервис входа — свой, на .NET: вход по телефону паролем и SMS-кодом, три роли в коде, без 2FA,
почты, своей админки и мгновенного отзыва. Новые проекты платформы должны получать вход готовым, а не писать его
заново. Песочница проверила Keycloak 26.4 на полном контракте боевого сервиса и на примере чужого проекта (магазин,
`samples/shop`).

## Решение

Сервер входа — **Keycloak**: пользователи, пароли, страницы входа, сессии, токены (OIDC), 2FA, ключи доступа,
журнал входов. Свой **сервис входа** (.NET) — обёртка: BFF для браузера, режимы, API админки и кабинета, ключи
сервисов, мгновенный отзыв, журнал действий. Сервисы проектов подключают пакеты `Platform.*` и проверяют токены сами,
без запроса к Keycloak.

## Последствия

- Пароли и секреты 2FA наш код не видит и не хранит; 2FA, passkey, SSO, защита от перебора — без своего кода.
- Остаётся свой код: плагин Keycloak на Java (~2 300 строк), сервис входа (~10 000), пакеты (~1 700), фронтенд
  (~7 700). Подробно — [выводы](../keycloak/08-conclusions.md#что-остаётся-своим-кодом).
- Keycloak — ещё одна система в эксплуатации: база, кластер, обновления.
- До боя ~4–6 недель ([оценка](../keycloak/08-conclusions.md#до-боя)).
- После переноса существующего проекта (6а.5) — сверить решение с его журналом трений.

## Что отвергли

- **Свой сервер на OpenIddict** (было в песочнице до Keycloak, тег `openiddict-baseline`): страницы, хранение,
  2FA, сессии и защиту пришлось бы писать и сопровождать самим.
- **Облачные сервисы входа** (Auth0 и подобные) — не оценивали: данные пользователей вне компании и оплата за
  пользователя; при пересмотре стоит сравнить.
