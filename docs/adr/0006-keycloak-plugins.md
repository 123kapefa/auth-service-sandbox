# 0006. Свой код в Keycloak — только плагином, с проверками на каждое обновление

**Статус:** Предложено · **Дата:** 2026-10-05 · **Этапы:** 4, 5, 6, 6б

## Контекст

Части боевого контракта в Keycloak нет: вход по SMS-коду, номер телефона как логин в любом виде, BCrypt-пароли,
«закрыть одно приложение», оформление проекта из админки. Keycloak расширяется плагинами на Java (SPI). Часть SPI —
«внутренние» (`KC-SERVICES0047`): совместимость между версиями не обещана.

## Решение

- Всё своё в Keycloak — **один плагин** (`infra/keycloak/providers/code-login`), собирается в образе Keycloak вместе
  с темой. Форк Keycloak и правка его кода — нет.
- Своё — только там, где без него контракта нет: вход по коду, форма входа, BCrypt, доступ к приложению, маппер
  ролей по режиму, оформление и письма.
- **Каждое обновление Keycloak** — пересборка плагина и темы, тесты плагина и прогон всех `check-*.sh`.

## Последствия

- Нужен человек, который поддерживает Java внутри Keycloak; для команды на .NET — отдельный навык.
- Обновление Keycloak — ~0,5–1 день на минорную версию, больше — на мажорную.
- Лимиты кода живут в памяти Keycloak (сбрасываются при полном перезапуске) — до боя перенести в общее хранилище.

## Что отвергли

- **Вход по коду вне Keycloak** (свой сервис выдаёт токены) — две системы входа, сессии и SSO расходятся.
- **Форк Keycloak** — обновления становятся слиянием чужого кода.
