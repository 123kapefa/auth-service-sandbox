# 0002. Проект = realm, приложение = клиент, роль = режим

**Статус:** Предложено · **Дата:** 2026-10-05 · **Этапы:** 2, 4а, 6а

## Контекст

У компании несколько продуктов (магазин, соцсеть) со своими людьми. Внутри продукта — несколько приложений (сайт,
«Менеджер 1С»), аккаунт на них один, права в каждом свои. В боевом сервисе у человека одна роль, но сотрудник бывает и
покупателем — он переключает **режим**.

## Решение

- **Проект — realm Keycloak.** Свои пользователи, ключи подписи, страницы входа; проекты друг друга не видят. Новый
  проект — из шаблона (`scripts/project/create-project.sh`).
- **Приложение — клиент Keycloak.** Его роли — client roles; в токене только роли этого приложения (`aud` — код
  приложения).
- **Роль = режим.** Ролей у человека сколько угодно; работает он в одной (`active_mode`, свой в каждом приложении).
  Режим не выбран — роль по умолчанию приложения. Права в токене — только по текущему режиму.

## Последствия

- Изоляция проектов — средствами Keycloak, без своего кода.
- `available_roles` в токене — массив, а в боевом — строка через запятую: при переезде менять потребителей или
  маппер.
- Режим меняет сам человек (`POST /auth/mode { app, activeMode }`, кабинет) — новый токен без перелогина.

## Что отвергли

- **Один realm на всё, проекты — группами.** Общие пользователи и ключи подписи, изоляция — своим кодом.
- **Режим как отдельная сущность рядом с ролями** — две модели вместо одной, без выгоды.
