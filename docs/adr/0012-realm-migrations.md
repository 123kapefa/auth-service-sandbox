# 0012. Настройки проектов — нумерованными миграциями, версия — в realm

**Статус:** Предложено · **Дата:** 2026-10-08 · **Этап:** 11.6

## Контекст

Настройки проекта живут в realm Keycloak: сценарии входа, действия, клиенты, роли, права, CSP. Realm импортируется из
JSON-шаблона (`infra/keycloak/realm/sandbox-realm.json`) только в пустую базу, поэтому изменения шаблона получают
только новые проекты. Проектам, созданным раньше, этапы 6б и 10 давали разовые скрипты (`upgrade-6b.py`,
`upgrade-10.py`): их запускали руками, и нигде не было записано, к какому проекту что применено. Проектов на одном
Keycloak может быть много, и каждый создан на своей версии.

## Решение

- **Нумерованные миграции** `scripts/project/realm-migrations/NNNN-коротко.py`, у каждой `apply(admin)`. Миграция
  **идемпотентна** (создаёт, если нет; включает, если выключено) и не трогает своё у проекта: название, оформление,
  ключи внешних входов, приложения, свои значения CSP. Применённую не правят — исправление следующей.
- **Версия — в самом realm**, атрибут `platform.realmVersion`; нет атрибута — версия 0. Новые проекты получают
  последнюю версию из шаблона.
- **Мигратор** (`migrate-realms.py`, образ `platform-auth-realm-migrator`) проходит все проекты — realm с клиентом
  `auth-api` — и применяет недостающие миграции по порядку, записывая версию после каждой. Запускается при каждом
  развёртывании до старта сервиса: в compose — `depends_on: service_completed_successfully`, в Kubernetes — хук Helm
  после нового Keycloak.
- **Только вперёд**, как и у базы сервиса (EF): откат — новой миграцией или из резервной копии.

## Последствия

- Обновление версии сервиса входа больше не требует ручных скриптов для старых проектов, а `--status` показывает
  версию каждого проекта.
- Каждое изменение шаблона, нужное старым проектам, делается дважды: в JSON и миграцией; проверка
  `check-realm-migrations.sh` откатывает realm песочницы и применяет все миграции заново.
- Миграция работает с Admin API Keycloak: шаг, которого нет в Admin API, миграцией не сделать.
- Версия realm новее мигратора (развернули старый образ) — проект пропускается; откат образа не откатывает realm.
- Атрибуты realm пишутся только поверх текущих: `PUT` realm с `attributes` заменяет их все.

## Что отвергли

- **Разовые скрипты на каждый этап** — так было: неизвестно, что применено, и порядок держится в голове.
- **Переимпорт realm из JSON** (`--override`) — затирает пользователей и своё у проекта.
- **Учёт применённого в базе сервиса** — версия отдельно от realm расходится с ним при восстановлении копии Keycloak
  или переносе проекта; атрибут переезжает вместе с realm.
- **keycloak-config-cli** — приводит realm к декларативному описанию; чтобы не затереть своё у проекта, надо тонко
  настраивать, чем он управляет, а шаги наших плагинов (`enable-*.py`) всё равно остаются скриптами. Ещё один
  инструмент на Java в поставке.
