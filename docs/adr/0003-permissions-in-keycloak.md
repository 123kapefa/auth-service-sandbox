# 0003. Права и роли — в Keycloak, объявляет их код приложения

**Статус:** Предложено · **Дата:** 2026-10-05 · **Этапы:** 4а, 6а.4

## Контекст

В боевом сервисе карта «роль → права» в коде: поменять состав роли — новый релиз. Проектам нужны свои роли и
быстрые правки, но проверяет права всё равно код, и право, которого код не знает, бесполезно, а опечатка в имени даёт
молчаливый 403.

## Решение

- Право — client role приложения, роль — составная роль из прав. Права в токене (`permissions`) — по режиму;
  сервис проверяет их локально (`RequirePermissions`).
- **Права объявляет код приложения** (`AddAppCatalog` в пакете `Platform.AuthService.Client`): при старте сервис
  отправляет каталог своим ключом. Права из кода в админке не удалить.
- **Роли из кода создаются один раз**, дальше их составом управляет админ проекта или приложения; перезапуск сервиса
  правки не откатывает.
- Смена роли или её состава действует сразу: 401 `access_changed` → refresh без перелогина (умный рефреш).

## Последствия

- Права не забывают завести и не опечатываются; состав ролей меняют без релиза.
- Каталог приложения читается из Keycloak на каждый запрос админки (без кэша) — для больших проектов нужна своя
  модель чтения.
- Право, исчезнувшее из кода, не удаляется автоматически (может быть в ролях) — сервис пишет его в лог.

## Что отвергли

- **Права только в коде** (как в боевом) — правка роли требует релиза.
- **Права только в админке** — расходятся с кодом, опечатки не видны (трение №4 в [журнале](../keycloak/06a-friction.md)).
- **Authorization Services Keycloak (UMA, политики)** — проверка с запросом к Keycloak на каждое действие; нам
  хватает прав в токене.
