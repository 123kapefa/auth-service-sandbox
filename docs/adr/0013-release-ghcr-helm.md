# 0013. Релиз тегом: образы в GHCR, пакеты в GitHub Packages, в Kubernetes — Helm

**Статус:** Предложено · **Дата:** 2026-10-08 · **Этап:** 11.2, 11.7

## Контекст

Сервис входа поставляется проектам как компонент: три образа (сервис, Keycloak с плагином и темой, мигратор настроек
проектов) и три NuGet-пакета для сервисов проекта. До этапа 11 их собирали руками на машине
(`scripts/package/*`), версия нигде не закреплялась, а запускать можно было только через Docker Compose. Нужно, чтобы
версию выпускал кто угодно из команды, а ставил её проект — по документу.

## Решение

- **Релиз — тегом `vX.Y.Z`.** Workflow `release.yml` собирает и публикует всё сам; версия одна на пакеты, образы и
  чарт (`VersionPrefix`, `Chart.yaml`, `deploy/.env.example`), расхождение с тегом или между собой — релиз падает.
- **Образы — в GHCR** (`ghcr.io/123kapefa/platform-auth-*`), **пакеты — в GitHub Packages**. Публикует CI своим
  токеном (`GITHUB_TOKEN`), права и видимость — от репозитория. Реестр и фид компании — переменной
  (`AUTH_REGISTRY`, `images.registry`, `nuget.config`), образы те же.
- **Kubernetes — Helm-чарт** `deploy/helm/platform-auth`: сервис и Keycloak по две реплики, миграторы — Job-хуки
  (база сервиса до раскатки, настройки проектов после нового Keycloak), секреты — оператор Infisical. Тег образов по
  умолчанию — версия чарта. Docker Compose (`deploy/compose.yaml`) остаётся для одной машины.

## Последствия

- Выпуск — PR с номером версии и тег ([release.md](../release.md)); тег ставит тот, у кого есть право push тегов.
- Опубликованный пакет не перевыпустить: исправление — новая версия. Образы при повторном запуске перезаписываются.
- Читать закрытые пакеты и образы — с токеном GitHub (`read:packages`), в кластере — Secret для скачивания образов.
- Поставка завязана на GitHub; переезд в реестр компании — смена адреса, не сборки.
- Чарт ставится из репозитория на теге версии, отдельного репозитория чартов нет.

## Что отвергли

- **Docker Hub или реестр компании по умолчанию** — отдельные учётки и секреты в CI; реестра компании пока нет.
- **Простые манифесты Kubernetes** — порядок миграторов пришлось бы держать руками, а значения проекта — правкой копий
  манифестов.
- **Kustomize** — накладки удобны для окружений одного проекта, но хуков с порядком у него нет.
- **Публикация чарта в OCI-реестр** — пока чарт ставит одна команда из репозитория; можно добавить в релиз позже.
