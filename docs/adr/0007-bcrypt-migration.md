# 0007. Перенос пользователей с BCrypt-паролями, перехеш при первом входе

**Статус:** Предложено · **Дата:** 2026-10-05 · **Этап:** 6

## Контекст

В боевой базе пароли — BCrypt (cost 12). Keycloak BCrypt не знает. Просить всех сменить пароль при переезде нельзя.

## Решение

- Разовый перенос (`src/AuthService.LegacyImport`): тот же Id, логин, роли, блокировка и BCrypt-хэш как есть —
  через Admin API от временного клиента `legacy-import`.
- Плагин `bcrypt` (публичный SPI `PasswordHashProvider`) проверяет старый хэш; при первом входе Keycloak
  перехеширует пароль в argon2.
- Переезд — в окне, когда боевой сервис только на чтение; после — клиент `legacy-import` удалить.

## Последствия

- Пользователи входят старым паролем; первый вход дольше на ~0,25 с один раз. 10 000 человек переносятся за ~53 с.
- Сессии боевого сервиса не переносятся — все входят заново. Временные блокировки не переносятся.
- Плагин `bcrypt` живёт, пока у кого-то остаётся старый хэш; через несколько месяцев таких можно оставить без пароля
  (войдут по коду).

## Что отвергли

- **Сброс паролей всем** — массовые письма и SMS, потеря пользователей.
- **Перенос «на лету» при входе** (User Storage SPI к старой базе) — старая база нужна живой всё время переезда.
