# 0011. Секреты — в Infisical, утечки ловит gitleaks, смена — с перекрытием

**Статус:** Предложено · **Дата:** 2026-10-08 · **Этап:** 11.5

## Контекст

Секреты сервиса входа лежали в `.env` и PFX-файле на машине: кто видит машину, видит все секреты; поменять их было
нечем, а проверки, что секрет не ушёл в git, не было. Kalmykov-Group/auth-service держит секреты в Infisical и
проверяет репозиторий gitleaks в CI (сравнение — `compare-kalmykov.md` в файлах проекта).

## Решение

- **Хранилище — Infisical**: проект `auth-service`, окружения dev, staging, prod. Секреты подставляются переменными
  окружения при запуске (`infisical run -- docker compose up`; в Kubernetes — оператор Infisical), на диск не пишутся.
  Сертификат DataProtection — тоже строкой (PFX в base64).
- **Утечки — gitleaks**: вся история в CI на каждый push и pull request, и перед коммитом (pre-commit). Исключения —
  только заглушки разработки и идентификаторы, с пояснением.
- **Смена без отказов там, где проверяющий — наш код**: сервис входа помнит прежний секрет BFF и прежний
  сертификат DataProtection на время смены; старые ключи DataProtection перешифровываются новым сертификатом при
  старте. Для каждого секрета описано, как сменить и что ломается ([docs/secrets.md](../secrets.md)), где можно —
  скрипт.

## Последствия

- На машине остаётся один секрет — вход в хранилище (учётка машины); в Kubernetes его нет совсем (Kubernetes Auth).
- Запуск зависит от доступности Infisical: без него не стартовать (уже запущенные сервисы работают).
- Переменные окружения контейнера видны через `docker inspect` — защита от того, у кого есть Docker на машине, это
  доступ к машине, а не хранилище.
- Пароль почты и ключи внешних систем меняются вручную по описанию: их проверяют чужие системы.

## Что отвергли

- **HashiCorp Vault** — больше возможностей (динамические пароли баз), но его надо держать и разворачивать
  отдельно; для набора статических секретов сервиса входа избыточен.
- **Docker/Kubernetes secrets без хранилища** — секреты всё равно где-то лежат открытым текстом (файл на машине,
  манифест), нет истории изменений и прав по окружениям.
- **Встроенная смена секрета клиента Keycloak** (client secret rotation) — preview-функция Keycloak; сервису входа
  проще самому помнить прежний секрет.
