# Перенос пользователей из старого сервиса

Если у вас уже есть сервис входа с живыми пользователями и паролями BCrypt: люди входят **старым паролем**, без сброса и
писем «придумайте новый». Идентификаторы пользователей сохраняются, поэтому ссылки других сервисов (заказы и т. п.) не
ломаются.

## Как это работает

1. Инструмент `src/AuthService.LegacyImport` читает таблицу `users` старого сервиса и загружает людей в Keycloak пачками по
   500: Id, логин, роли, блокировка, BCrypt-хэш.
2. При первом верном входе Keycloak проверяет пароль плагином по BCrypt (первые 72 байта, как в BCrypt.Net) и тут же
   заменяет хэш своим (argon2). Плагин `bcrypt` нужен, пока есть непереехавшие хэши.
3. Люди без пароля входят по коду.

## Как перенести

1. Остановить запись в старый сервис (нужно окно без записи: повторный прогон не обновляет уже перенесённых).
2. Проверить без записи:

   ```bash
   DOTNET_ENVIRONMENT=Development dotnet run --project src/AuthService.LegacyImport -- --dry-run
   ```

3. Выполнить перенос (в бою — режим `SKIP`: существующих не трогать). Инструмент использует временный клиент
   `legacy-import` с широким правом `manage-realm`; **удалите клиент сразу после переноса**.
4. Переключить приложения на сервис входа. Сессии и refresh-токены старого сервиса не переносятся — все войдут заново.
   Временные блокировки и счётчики неудачных входов тоже не переносятся.

## Что учесть

- Старые логины вида `+79991110001` становятся `79991110001`, телефон хранится в атрибуте `phone` как `+7…`.
- Роли без пары в новом сервисе (например `courier`) переносятся покупателем с пометкой — решение за админом.
- Если в старом сервисе не было почты, у перенесённых её нет: сброс пароля — по телефону и коду.
- Каждый перенесённый получает роль по умолчанию `customer`.
- Если в пачке Id уже занят под другим логином, пачка не загрузится — повторить по одному.
- `available_roles` в токене — массив, а в старом сервисе была строка: проверьте потребителей.

## Проверить

Скрипт `scripts/keycloak/check-migration.sh` пересоздаёт «боевую» тестовую базу (`scripts/legacy/seed-legacy.sh`) и проходит
весь путь: перенос, вход старым паролем, перехеш, повторный прогон. Нужен .NET SDK.
