# Что это

Сервис входа — готовый компонент для ваших приложений. Он отвечает на вопросы «кто это» и «что ему можно», а ваши
сервисы проверяют токен и работают дальше. Основа — Keycloak, вокруг него — наши страницы входа, админка, личный
кабинет и пакеты для сервисов.

## Что умеет

**Вход**
- Телефон или почта, пароль; сброс пароля по письму.
- Вход по коду: на телефон звонком (последние 4 цифры), SMS — запасным путём; код на почту.
- Двухфакторная защита (приложение-аутентификатор, коды восстановления) по желанию; ключи доступа (passkey) без пароля.
- Вход через Яндекс ID и Госуслуги.
- Человек сам выключает ненужные способы входа; проект задаёт рамки.
- Защита от накрутки кодов: лимиты, капча, дневной бюджет, письма админам.

**Доступ**
- Проекты, которые друг друга не видят; в проекте — сколько угодно приложений.
- Свои роли и права у каждого приложения; у человека несколько ролей, работает он в одной (режим).
- Изменения действуют сразу: блокировка и закрытие доступа отзывают токены мгновенно, смена роли не выкидывает человека.
- Администратор проекта и администратор отдельного приложения.
- Журнал действий и входов.

**Для разработчика**
- Пакеты `Platform.*`: проверка токена, роли и права, мгновенный отзыв — несколько строк в `Program.cs`.
- Ключ у каждого сервиса: сервисы ходят друг к другу только туда, куда им разрешено.
- Страницы входа и письма в стиле проекта без пересборки.
- Развёртывание: Docker Compose или Kubernetes (Helm).

## Как это выглядит

```
                   ┌────────── сервер входа (Keycloak) ──────────┐
 человек ──вход──▶ │ проект = realm: люди, приложения, их роли   │ ◀── ключ сервиса
                   └───────▲───────────────────────────▲────────┘
                           │ админка, кабинет, API     │ токены
                   сервис входа проекта       сервисы проекта
```

## Термины

| Термин | Значение |
|---|---|
| **Проект** | отдельный продукт со своей базой людей (интернет-магазин, соцсеть). Проекты друг друга не видят |
| **Приложение** | сайт или программа внутри проекта (сайт магазина, менеджер 1С). Аккаунт один на проект, права в каждом приложении свои |
| **Право** | действие, которое можно разрешить (`orders.view`) |
| **Роль** | набор прав (`customer`, `manager`) |
| **Режим** | роль, в которой человек работает сейчас; ролей может быть несколько |
| **Админ проекта** | управляет людьми и всеми приложениями проекта |
| **Админ приложения** | управляет ролями и доступом только своего приложения |
| **Ключ сервиса** | пара `client_id` и секрет, по которой сервис получает токен |
