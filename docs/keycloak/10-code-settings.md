# Этап 10.7. Коды и способы входа проекта в API админки

**Статус:** ✅ API готов (экраны админки — в 10.10) · **Задача:** [#135](https://github.com/123kapefa/auth-service-sandbox/issues/135) (этап 10 — [#128](https://github.com/123kapefa/auth-service-sandbox/issues/128))

Админ проекта сам решает, как слать коды подтверждения и сколько на них тратить, и видит расход за сегодня — без
перезапуска Keycloak и правки настроек сервера, и включает или выключает способы входа проекта
([ниже](#способы-входа-проекта)). Экраны админки «Вход и коды» (15) и «Способы входа» (22) — в 10.10; здесь — API.

## Что меняет админ

| Настройка | Поле API | Атрибут realm | Пусто в проекте — берётся |
|---|---|---|---|
| Звонки и/или SMS на телефон (звонок всегда первым) | `phoneChannels`: `call`, `sms` | `platform.codes.phone-channels` | из настроек сервера, по умолчанию оба |
| Страны (код без «+») | `countries`: `7`, `375` | `platform.codes.countries` | `7` |
| Дневной бюджет, копейки (0 — без бюджета) | `dailyBudget` | `platform.codes.daily-budget` | 1000 ₽ |
| На номер в час и в сутки | `targetPerHour`, `targetPerDay` | `…target-per-hour`, `…target-per-day` | 5 и 10 |
| С одного IP в час | `ipPerHour` | `…ip-per-hour` | 10 |
| На диапазон номеров в час | `rangePerHour` | `…range-per-hour` | 20 |
| Капча после отправок за час | `captchaAfter` | `…captcha-after` | 2 |

Ограничения: хотя бы один способ на телефон; от 1 до 20 стран; бюджет — до 10 млн ₽; в сутки на номер — не меньше,
чем в час. Неверное не сохраняется (сервис и плагин проверяют одинаково). Цены звонка и SMS, пауза перед повтором,
длина диапазона, порог оповещения и часовой пояс суток — только настройками сервера: в ответе они есть, но не
меняются.

Изменение — в журнал проекта: `ProjectCodesChanged`, только изменённые поля `{ old, new }`. Плагин применяет
настройки со следующей отправки кода.

## Расход за сегодня

Сутки — по часовому поясу бюджета (Москва), с полуночи. Сколько ушло звонков, SMS и писем и во что обошлись, бюджет
(израсходовано из скольких, кончился ли) и сколько кодов введено верно — доля введённых (`verifiedPercent`, null —
ничего не отправлено). Низкая доля — главный признак накрутки ([10.1](10-code-limits.md#оповещения-и-метрики)).
Считаются коды и входа, и смены номера; код, который не ушёл (способ выключен у человека), — нет.

Счётчики суток — в общем хранилище Keycloak рядом с расходом бюджета (одна запись на сутки, хранится двое суток).
Письмо админам при 80 % и 100 % бюджета — позже; пока — строка в логе и метрика (10.1).

## API

| Метод | Право | Что |
|---|---|---|
| `GET /auth/admin/codes/settings` | `sign-in.manage` | настройки, по которым коды уходят сейчас |
| `PUT /auth/admin/codes/settings` | `sign-in.manage` | сохранить всё, что меняет админ, целиком |
| `GET /auth/admin/codes/usage` | `sign-in.manage` | расход за сегодня |
| `GET /auth/admin/sign-in/methods` | `sign-in.manage` | способы входа проекта и 2FA |
| `PUT /auth/admin/sign-in/methods` | `sign-in.manage` | сохранить способы и 2FA целиком |
| `GET /auth/admin/sign-in/methods/{способ}/affected` | `sign-in.manage` | сколько людей входит способом и сколько — только им |

Право `sign-in.manage` — у роли `admin` (менеджеру — нет). Пример ответа расхода:

```json
{
  "date": "2026-10-07", "zone": "Europe/Moscow",
  "budget": { "spent": 150000, "limit": 300000, "alertPercent": 80, "exhausted": false },
  "call": { "sent": 1284, "cost": 103000 }, "sms": { "sent": 96, "cost": 47000 }, "email": { "sent": 412, "cost": 0 },
  "sent": 1792, "verified": 1630, "verifiedPercent": 91
}
```

## Как устроено

- Плагин: ресурс realm `/realms/{realm}/platform-codes` (`CodeSettingsResource`): `GET/PUT settings`, `GET usage`.
  Пускает только токен учётки с ролью realm **`manage-sign-in`** — она есть только у служебной учётки сервиса входа;
  `manage-realm` сервису не нужен. Проверка значений — `CodeSettings` (без Keycloak, с тестами).
- Сервис: `CodeSettingsHandler` (проверка, журнал) и `KeycloakCodes` (ходит в плагин токеном служебной учётки).
  Нет роли — `codes.not_permitted`, нет плагина (старый образ) — `codes.not_installed`.

## Способы входа проекта

Админ включает и выключает шесть способов: телефон (`phone`), почта (`email`), пароль (`password`), ключ доступа
(`passkey`), Яндекс ID (`yandex`), Госуслуги (`esia`), и делает 2FA обязательной или по желанию (`twoFactor`:
`required`, `optional`). Хранится в атрибутах realm `platform.sign-in.<способ>` (`on`, `off`,
`transition:<до yyyy-MM-dd>:<начало, мс>`) и `platform.sign-in.two-factor`; нет атрибута — включено.

- **Выключенный способ** не пускает и не регистрирует: номер или почту на форме входа не принимает с понятной
  подсказкой («Вход по номеру телефона в проекте выключен. Войдите по почте.»), код не шлёт, верный пароль отклоняет
  («Вход по паролю в проекте выключен…»), номер в кабинете не поменять. Ключ доступа, Яндекс ID и Госуслуги
  выключаются ещё и переключателями самого Keycloak (ключи доступа realm и регистрация ключа, identity provider) —
  мимо наших форм их не обойти.
- **Переходный период** — только у телефона, почты и пароля, до даты в будущем, не дальше года (сутки — по Москве).
  В период способ остаётся только тем, кто был заведён до его начала и входит **только** этим способом; новых людей
  им не регистрируем. После входа таким способом человеку каждый раз предлагают добавить ключ доступа
  (экран предложения 10.6 с датой окончания, без паузы после «Не сейчас»). После даты способ выключен.
- **Хотя бы один способ регистрации** (телефон, почта, Яндекс ID, Госуслуги) должен остаться включённым.
- **2FA обязательна** — тому, у кого нет приложения-аутентификатора, при следующем входе сразу предлагают его завести.
- Внешний вход, который в Keycloak не настроен или выключен, показан выключенным; `configured` — настроен ли он
  (ключи проекта есть).

Перед выключением админка спрашивает, сколько людей входит этим способом и сколько — **только** им (их выключение
запрёт): `GET …/{способ}/affected`. Считает перебором всех людей проекта — на большом проекте медленно.

Изменение — в журнал проекта: `ProjectSignInChanged` («Способы входа»), только изменённое `{ old, new }`, например
`phone: { old: "on", new: "transition до 2026-11-06" }`.

Плагин: ресурс realm `/realms/{realm}/platform-sign-in` (`SignInSettingsResource`, та же роль `manage-sign-in`),
правила — `ProjectSignIn` (без Keycloak, с тестами), применяют их формы входа, вход по коду, смена номера и последний
шаг входа (`AppAccessAuthenticator`). Сервис: `ProjectSignInHandler` и `KeycloakSignIn`; ошибки — `sign_in.*`
(`no_registration`, `transition_not_allowed`, `transition_date`, `not_permitted`, `not_installed`).

Пока не сделано: в кабинете и в способах входа человека (`/me/sign-in-methods`) выключенные в проекте способы ещё
видны — уберём в 10.9 и 10.10. Подпись поля логина по способам проекта — в [10.8](10-login-theme.md).

## Старый стенд

Realm импортируется только в пустую базу, поэтому на стенде, поднятом до 10.7:

```bash
docker compose up -d --build --wait                          # новый плагин и сервис
python3 scripts/project/enable-sign-in-settings.py sandbox   # роль manage-sign-in и право sign-in.manage
```

Админам проекта — войти в админку заново: право придёт с новым токеном.

## Проверка

```bash
scripts/keycloak/check-code-settings.sh
scripts/keycloak/check-project-sign-in.sh
```

Ожидается `Итого: 19 ✓, 0 ✗`: плагин без токена и с токеном человека — нет; у служебной учётки — `manage-sign-in`;
менеджеру — 403; вход по коду звонком — в расходе +1 звонок, +1 ₽, +1 введённый; «только SMS», страна, бюджет и
лимиты сохранены в realm, следующий вход — сразу SMS, без звонка; в журнале — что поменялось; неверное (без звонков и
SMS, страна с «+», в сутки меньше, чем в час, мимо сервиса прямо в плагин) — не сохраняется. В конце настройки проекта
снимаются.

`check-project-sign-in.sh` — `Итого: 43 ✓, 0 ✗`: только админу; сколько входят по телефону; неверное (без способов
регистрации, переходный период ключа, прошлая дата, мимо сервиса) — не сохраняется; пароль выключен — верный пароль
не пускает, по коду входит; телефон выключен — по номеру нет (звонка нет), по почте — да, незнакомый номер не
регистрируется; переходный период — «старый» человек только с телефоном входит и при каждом входе видит предложение
ключа, у кого есть почта и кто заведён после начала — нет; 2FA обязательна — сразу настройка приложения; ключ доступа
и Яндекс ID выключены в самом Keycloak и пропадают со страницы входа. В конце всё включается обратно.
