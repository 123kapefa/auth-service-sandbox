# Этап 10. Вход: способы входа и коды подешевле

**Статус:** ✅ готово · **Задача:** [#128](https://github.com/123kapefa/auth-service-sandbox/issues/128) (итог — [#139](https://github.com/123kapefa/auth-service-sandbox/issues/139))

Итог этапа. Вопросы этапа: как дать человеку закрыть ненужные способы входа (утёкший пароль, перевыпущенный номер) и
как сделать коды дешевле и защищённее от накрутки. Подробности — в документах подзадач, решения — в
[ADR 0009](../adr/0009-sign-in-methods-chosen-by-person.md) и [ADR 0010](../adr/0010-codes-call-before-sms.md).

## Коротко

- **Человек сам выбирает, как в него войти**: выключает пароль, код на телефон или почту в кабинете; без ключа
  доступа или приложения-аутентификатора пароль и телефон не выключить, хотя бы один способ остаётся всегда.
- **Проект задаёт рамки**: админ проекта включает и выключает способы входа (с переходным периодом), делает 2FA
  обязательной, задаёт каналы, страны, бюджет и лимиты кодов — в своей админке, без перезапуска Keycloak.
- **Коды дешевле**: код на телефон — звонком-сбросом (4 цифры), SMS — только запасным путём; после входа по коду
  предлагаем ключ доступа.
- **Коды защищены от накрутки**: пауза, лимиты на номер, IP и диапазон, страны, капча, дневной бюджет (выключает
  только SMS), письма админам при 80 % и 100 %, метрики.
- **Вход в два шага** (логин → способ), смена номера самим человеком, страницы входа, кабинет и админка — по
  макетам этапа.

## Как устроено

| Где | Что |
|---|---|
| Плагин Keycloak (`infra/keycloak/providers/code-login`) | вход по коду и два шага (`CodeLoginAuthenticator`), лимиты и капча (`CodeLimits`, `CodeLimitPolicy`), отправка и бюджет (`CodeDispatcher`, `BudgetAlerts`), телефония (`PhoneProvider`), способы человека (`SignInMethods`) и проекта (`ProjectSignIn`), смена номера (`platform-update-phone`), предложение ключа (`platform-passkey-offer`), ресурсы realm для сервиса (`platform-codes`, `platform-sign-in`) |
| Сервис входа (`src/AuthService.*`) | API кабинета (`/me/sign-in-methods`) и админки (`/auth/admin/codes/*`, `/auth/admin/sign-in/*`, сброс способов человека), те же правила (`SignInMethodRules`), письмо об изменении, журнал |
| Тема входа (`login-theme/`) | экраны по макетам: шаги, способы, звонок, SMS, письмо, капча, смена номера, 2FA, «Входите без кода»; письма о способах входа и бюджете |
| Админка и кабинет (`frontend/`) | кабинет — «Способы входа», номер в профиле; админка — «Вход и коды», способы входа в карточке пользователя |
| Realm (`infra/keycloak/realm/sandbox-realm.json`) | действия `platform-update-phone` и `platform-passkey-offer`, роль `manage-sign-in` у служебной учётки и право `sign-in.manage`, CSP для капчи |

Настройки проекта — атрибуты realm (`platform.codes.*`, `platform.sign-in.*`), настройки человека — атрибуты
пользователя (`disabled_sign_in_methods`, `passkey_offer_skipped_at`). Счётчики кодов и бюджета — в общем хранилище
Keycloak. Миграций базы сервиса этап не добавил.

попросит перезапустить Keycloak: `docker compose restart keycloak`.

## Стенд и проекты, созданные раньше

Realm импортируется только в пустую базу, поэтому стенду и проекту, созданным до этапа 10, — одна команда после
`git pull` и `docker compose up -d --build --wait`:

```bash
python3 scripts/project/upgrade-10.py sandbox
```

Включает действия смены номера и предложения ключа, роль `manage-sign-in` у служебной учётки и право
`sign-in.manage` в роли `admin`, добавляет капчу во `frame-src` CSP realm (свой CSP не затирает). Повторный запуск
ничего не ломает. Админам проекта — войти заново: право придёт с новым токеном. Новые проекты получают всё из шаблона
realm. Прежние `enable-phone-change.py`, `enable-passkey-offer.py`, `enable-sign-in-settings.py` остаются — для
одного шага.

## Ограничения и что до боя

| Что | Сейчас | До боя |
|---|---|---|
| Телефония | заглушка `idp-stub` (страница «Звонки и SMS») или лог Keycloak | выбрать провайдера (звонок-сброс и SMS в одном API), подключить реализацию `PhoneProvider` |
| Капча | заглушка стенда (`sandbox-captcha-ok`) | ключи Яндекс SmartCaptcha; без ключа после порога код не уходит |
| Счётчики лимитов | не атомарны: при одновременных запросах лимит может пропустить лишнюю отправку | принято; при кластере — проверить под нагрузкой |
| «Сколько людей входят только так» | перебор всех людей проекта при открытии окна выключения | на большом проекте — счётчик или фоновый подсчёт |
| Ключ доступа и коды восстановления | можно удалить на странице Keycloak в обход правил; страховка плагина возвращает выключенное | закрыть кабинет Keycloak (`account-console`) — решить отдельно |
| Способы входа для одного приложения | нет: вход общий на проект (SSO) | step-up для приложения, если понадобится |
| «Отвязать» Яндекс ID и Госуслуги в кабинете | нет действия в сервисе | правила «последний способ», письмо, журнал |
| Ключи доступа в карточке пользователя | «есть / нет», без названий и числа кодов восстановления | при необходимости — расширить API админки |
| Сменить номер за человека | только в админке Keycloak | своя кнопка в админке, если понадобится |
