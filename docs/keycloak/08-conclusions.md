# Этап 8. Выводы

**Статус:** ✅ готово, решения приняты (2026-10-05; дополнено после этапа 10 — 2026-10-07) · **Задача:** [#54](https://github.com/123kapefa/auth-service-sandbox/issues/54)

Вопрос этапа: **брать ли Keycloak сервером входа платформы, чего это стоит и что остаётся своим кодом.** Ответ — ниже,
решения по отдельности — в [docs/adr](../adr/README.md).

## Коротко

**Брать.** Keycloak закрыл всё, что делает боевой сервис входа, и больше: вход по паролю и коду, почта и телефон,
2FA, ключи доступа (passkey), сессии и SSO на все приложения проекта, журнал входов, защиту от перебора, проекты,
которые друг друга не видят. Пароли и секреты 2FA наш код больше не видит. Всё это проверено на стенде скриптами
(больше 600 проверок на стенде и ~750 тестов) и примером чужого проекта — магазином из двух сервисов.

Цена — не в самом Keycloak, а в том, что вокруг него остаётся своим:

1. **Свой код в Keycloak на Java** (вход по коду, проверка BCrypt, доступ к приложению, оформление) — ~2 300 строк.
   Часть сидит на «внутреннем» API Keycloak: каждое обновление Keycloak — пересборка и прогон проверок.
2. **Сервис входа на .NET** — админка, кабинет, ключи сервисов, мгновенный отзыв, журнал — ~10 000 строк, общие пакеты
   ~1 700 и фронтенд ~7 700 строк. Это то, что делает Keycloak удобным для наших проектов; без него Keycloak — только
   его собственная админка.
3. **Эксплуатация Keycloak** — ещё одна система с базой, кластером, обновлениями и мониторингом.

До боя нужно ~3–5 недель одного разработчика (таблица ниже; после этапа 10) и человек, готовый поддерживать Java внутри Keycloak.

**Чего не проверили:** перенос существующего проекта на живом коде (шаг 6а.5 — отложен), нагрузку, кластер
Keycloak, настоящего провайдера звонков и SMS. Решение принято; после 6а.5 — сверить с её журналом трений.

**После этапа 10** ([10-login-methods.md](10-login-methods.md)) вывод тот же, а вход стал заметно сильнее и
дешевле — всё на том же расширении Keycloak плагином, без форка: человек сам выключает пароль и коды, проект задаёт
способы входа и бюджет кодов, код на телефон — звонком, SMS — запасным путём, защита от накрутки закрыла главный
денежный риск. Плагин вырос до ~6 000 строк Java (вместе с этапом 9), тема — до ~3 300, фронтенд — до ~7 900; это
та же цена «своего кода в Keycloak», только больше.

## Что остаётся своим кодом

Строки — без тестов и миграций, на момент этапа 8.

| Часть | Строк | Зачем | Можно ли без неё |
|---|---|---|---|
| **Плагин Keycloak** (`infra/keycloak/providers/code-login`, Java) | ~2 300 | вход по коду, форма входа с нормализацией номера, BCrypt, «доступ к приложению закрыт», маппер ролей по режиму, оформление и письма | нет: без него нет входа по SMS и переноса паролей — главного в боевом контракте |
| **Тема входа и писем** (`login-theme/`, React + FreeMarker) | ~1 500 | страницы входа и письма на русском, в стиле проекта | можно со стандартной темой Keycloak, но выглядит чужеродно |
| **Сервис входа** (`src/AuthService.*`, .NET) | ~10 000 | BFF (вход, cookie, refresh, выход), режимы, API админки и кабинета, ключи сервисов, каталог прав из кода, журнал действий, устройства | нет: Admin API Keycloak нельзя отдавать браузеру, своих правил (режимы, админ приложения, step-up) в Keycloak нет |
| **Общие пакеты** (`src/Shared`, `Platform.*`) | ~1 700 | проверка токена, режимы и права, мгновенный отзыв, токен по ключу | нет: их подключает каждый сервис проекта |
| **Админка и кабинет** (`frontend/`) | ~6 200 | свой интерфейс вместо админки и кабинета Keycloak | админку Keycloak нельзя давать админам проектов — она про всё |
| **Перенос пользователей** (`src/AuthService.LegacyImport`) | ~550 | разовый перенос из боевой базы | после переезда не нужен |
| **Скрипты проекта и проверки** (`scripts/`) | ~3 500 | создать проект, приложение, админа; проверки стенда | проверки нужны для каждого обновления Keycloak |

Главное: **пароли, секреты 2FA и ключи доступа — только у Keycloak**. Сервис входа их не видит (кабинет просит
действие у Keycloak — `kc_action`), а значит, самое опасное в коде входа — не наше.

## Чего это стоит

### До боя

Грубо, в днях одного разработчика, который знает этот код.

| Что | Оценка | Откуда |
|---|---|---|
| Вход по коду до прод-качества: провайдер звонков и SMS, ключи капчи, тесты плагина в CI (лимиты по IP и от накрутки, общее хранилище, HTML-письма и метрики сделаны в этапе 10) | 1 неделя | [этап 5](05-code-login.md#оценка-до-прод-качества), [этап 10](10-login-methods.md#ограничения-и-что-до-боя) |
| Кластер Keycloak (2+ узла, общий кэш), резервные копии базы, мониторинг и оповещения | 1 неделя | не делали |
| Перенос существующего проекта на живом коде (6а.5) и правки по его журналу трений | 1 неделя | [этап 6а](06a-embedding.md) |
| Хвосты из «Ограничений» ниже: ответы 401/403 в `Envelope`, `available_roles` строкой (если нужна совместимость), нормализация номера в сбросе пароля ([#57](https://github.com/123kapefa/auth-service-sandbox/issues/57)) | 2–3 дня | этапы 2, 3, 5 |
| Нагрузочный прогон: вход, refresh, проверка отзыва | 2–3 дня | не делали |
| **Итого** | **~3–5 недель** (было ~4–6 до этапа 10) | |

### Постоянно

- **Обновления Keycloak** — пересборка плагина и темы, прогон всех `check-*.sh`: ~0,5–1 день на минорную версию,
  больше — на мажорную. Аутентификаторы — внутренний SPI (`KC-SERVICES0047`), совместимость не обещана.
- **Java в команде на .NET.** Плагин небольшой, но нужен человек, который его поддерживает.
- **Keycloak в эксплуатации:** своя база, обновления схемы при апгрейдах, кластер, журнал событий (30 дней).
- **Коды** — стоимость звонков и SMS; от накрутки — лимиты, капча и дневной бюджет проекта (этап 10), следить за
  долей введённых кодов.

| аутентификаторы на «внутреннем» SPI | ⬜ **осталось, принято как цена**: прогон проверок на каждое обновление | [этап 5](05-code-login.md#ограничения-для-выводов) |

Ещё открыто (решить отдельно, на итог не влияет):

- кабинет Keycloak `account-console` включён — им можно пользоваться в обход своего кабинета ([6б](06b-account-branding.md#итоги-этапа));
- письмо «почта изменена» на старый адрес Keycloak не шлёт ([6б](06b-account-branding.md#итоги-этапа));
- вход без JavaScript невозможен — страницы рисует React; боевой вход работает и без него ([4в](04v-login-ui.md#ограничения-для-выводов));
- нет E2E-тестов в браузере: интерфейс — Vitest, путь пользователя — скриптами по API;
- внешние провайдеры входа: вместо Google и GitHub — Госуслуги и Яндекс ID, своими провайдерами в плагине, проверены
  на заглушке ([09-external-login.md](09-external-login.md), [#55](https://github.com/123kapefa/auth-service-sandbox/issues/55));
  для боя нужны ключи Яндекса и регистрация в ЕСИА с сервисом подписи ГОСТ.

## Чем отличается от боевого сервиса

Для тех, кто будет переезжать. Подробно — в разделах «Сравнение с боевым сервисом» этапов.

| | Боевой | На Keycloak |
|---|---|---|
| Роли | три в коде, у пользователя одна | свои у каждого приложения, сколько угодно; роль = режим |
| Права | карта в коде, новый релиз | в Keycloak (из кода сервиса или админки), действуют сразу |
| Смена роли | выход из всех сессий | умный рефреш: 401 `access_changed` → refresh без перелогина |
| Отзыв доступа | токен живёт до 15 минут | сразу |
| Админка | нет своей | своя: админ проекта и админ приложения |
| 2FA, ключи доступа, почта | нет | есть |
| Код на телефон | SMS | звонок-сброс, SMS — запасным; лимиты, капча, бюджет |
| Способы входа | одинаковые у всех | человек выключает ненужные, проект задаёт рамки |
| Страницы входа | Razor + htmx, работают без JS | React (Keycloakify), без JS не работают |
| Логин | `+79991110001` | `79991110001`, `phone` — `+7…` |
| `available_roles` | строка | массив |
| Сессии при переезде | — | не переносятся: все входят заново |

## Когда пересмотреть

- 6а.5 покажет, что существующий сервис нельзя перевести без переписывания его авторизации целиком.
- Новая версия Keycloak сломает аутентификаторы так, что починка дольше недели.
- Понадобится вход, который Keycloak не умеет и не расширяется SPI без форка.
