# Этап 6. Спайк: миграция пользователей с BCrypt

**Статус:** ✅ готово · **Ветка:** `stage-6/bcrypt-migration` · **Задача:** [#52](https://github.com/123kapefa/auth-service-sandbox/issues/52)

## Цель

В боевом сервисе есть живые пользователи с паролями. При переходе на Keycloak они должны войти **со старым паролем**,
без сброса и писем «придумайте новый пароль». Пароли хранятся отпечатками BCrypt (BCrypt.Net-Next, work factor 12),
а Keycloak «из коробки» BCrypt не проверяет; расшифровать отпечатки нельзя.

Решения (2026-10-02):

- **разовый импорт с хэшем**: пользователи и их BCrypt-хэши переносятся одним прогоном, Keycloak учится проверять
  BCrypt плагином; старая база после переезда не нужна. Ленивая миграция (User Storage SPI, перенос при первом входе)
  — не делаем: старая база жила бы до конца переезда, плагин сложнее;
- **перехэш при входе**: при первом верном входе Keycloak заменяет BCrypt своим хэшем (argon2), плагин потом можно убрать;
- **Id сохраняется**: другие сервисы хранят Id пользователя (заказы и т. п.) — ссылки не ломаются;
- **временный клиент `legacy-import`** с правом `manage-realm`: только импорт (`partialImport`) сохраняет Id, а он требует
  этого права; клиент живёт только на время переезда.

Тестовые данные — таблица со схемой боевой `users` и выдуманные пользователи; реальных данных в песочнице нет.

## Как устроено

```
legacy_auth.users (схема боевого auth-service)
        │  AuthService.LegacyImport: читает, сопоставляет, пачки по 500
        ▼
Keycloak Admin API  POST /admin/realms/sandbox/partialImport  (ifResourceExists=SKIP, клиент legacy-import)
        │  пароль: credentialData.algorithm = "bcrypt", secretData.value = "$2a$12$…"
        ▼
вход: плагин bcrypt проверяет пароль → Keycloak пересчитывает хэш в argon2
```

### Плагин: алгоритм `bcrypt`

`infra/keycloak/providers/code-login` (тот же jar, что вход по коду): `BcryptPasswordHashProvider` + фабрика
(`PasswordHashProviderFactory`, id `bcrypt`). Проверка — `BcryptHash` через BouncyCastle, который уже есть внутри
Keycloak: своих библиотек плагин не несёт. Как и BCrypt.Net, учитываются только первые 72 байта пароля.

Политика паролей realm на bcrypt не переключается. Поэтому после верного входа Keycloak видит «хэш не того алгоритма»
и сам пересчитывает его алгоритмом политики (в Keycloak 26 — argon2). Перенесённые BCrypt-хэши постепенно исчезают.

### «Боевая» база (infra/legacy/)

`schema.sql` — таблица `users` как в боевом сервисе (колонки, типы и индексы — из его снимка миграций), отдельная
база `legacy_auth` в Postgres песочницы. `seed.sql` — 9 выдуманных пользователей, по одному на случай:

| # | Телефон | Случай | Что в Keycloak |
|---|---|---|---|
| 1 | +79991110001 | покупатель с паролем | вход старым паролем |
| 2 | +79991110002 | без пароля (только SMS) | без пароля, вход по коду |
| 3 | +79991110003 | заблокирован админом, с причиной | `enabled=false`, `restriction_reason`, `restricted_at` |
| 4 | +79991110004 | менеджер | роль `manager` клиента `sandbox-api`, `active_mode=manager` |
| 5 | +79991110005 | администратор | роль `admin`, `active_mode=admin` |
| 6 | +79991110006 | курьер (роли в песочнице нет) | покупатель, `legacy_role=courier`, строка в отчёте |
| 7 | +79991110007 | временно заперт после неверных паролей | входит: в Keycloak своя защита от перебора |
| 8 | +79990000001 | номер уже занят в Keycloak | не переносится, конфликт в отчёте |
| 9 | +79991110009 | пароль кириллицей | вход старым паролем |

Пароль пользователя N — `Legacy-N!`, у 9-го — `Пароль-9!`. `scripts/legacy/seed-legacy.sh` пересоздаёт таблицу;
`--bulk N` добавляет N покупателей `+7997…` для замера.

### Инструмент переноса (src/AuthService.LegacyImport)

.NET-консоль в решении (строгие анализаторы, как у сервиса).

| Боевой сервис | Keycloak |
|---|---|
| `Id` | `id` — тот же |
| `Phone` (`+79991110001`) | `username` — цифрами; атрибут `phone` — как есть |
| `Role` | `customer` — роль по умолчанию; `manager`, `admin` — роли клиента `sandbox-api`; прочие — покупатель + `legacy_role` |
| — | `active_mode` — роль (для прочих — `customer`) |
| `IsRestricted`, причина, время | `enabled=false`, `restriction_reason`, `restricted_at` — как у блокировки в админке |
| `PasswordHash` (BCrypt) | пароль с `algorithm=bcrypt`, `hashIterations` — стоимость из хэша, дата — `PasswordSetAtUtc` |
| `PasswordHash` = NULL | без пароля — вход по коду |
| хэш не BCrypt | без пароля + строка в отчёте |
| `CreatedAt` | `createdTimestamp` |
| `LastLoginAtUtc`, `LoginCount` | атрибуты `legacy_last_login_at`, `legacy_login_count` |
| `FailedLoginAttempts`, `LockedUntilUtc` | не переносятся |

- **`partialImport`, `ifResourceExists=SKIP`.** Только импорт сохраняет Id (обычное создание выдаёт новый).
  Уже существующие логины пропускаются: тот же Id — «уже были», другой — конфликт (Keycloak возвращает Id занявшего).
- **Роль по умолчанию — явно.** Импорт, в отличие от создания пользователя, не выдаёт `default-roles-sandbox`
  (в ней `customer`) — инструмент указывает её сам.
- **Пачка отклонена целиком** (Id уже занят под другим логином — номер сменился после прошлого прогона) — инструмент
  повторяет её по одному и помечает виноватого ошибкой; остальные переносятся.
- **Отчёт** в лог: прочитано, перенесено, уже были, конфликты (кем занят номер), ошибки, сколько без пароля, сколько
  с непереносимой ролью. `--dry-run` — то же без записи. Код выхода 1, если есть ошибки.
- **Настройки**: `ConnectionStrings:Legacy`, `LegacyImport:Keycloak:{BaseUrl,Realm,ClientId,ClientSecret,RolesClientId}`,
  `LegacyImport:BatchSize`. В Development — заглушки в `appsettings.Development.json`; в бою строка подключения и
  секрет — только из переменных окружения (`ConnectionStrings__Legacy`, `LegacyImport__Keycloak__ClientSecret`).

### Клиент `legacy-import`

Конфиденциальный, только служебная учётка (без входа пользователей), роли `realm-management`: `manage-realm`
(нужна `partialImport`), `manage-users`, `view-users`. Секрет — `LEGACY_IMPORT_CLIENT_SECRET`. В песочнице живёт
постоянно (для проверок); в бою — создать перед переездом, удалить сразу после. В журнале Keycloak видно, что
изменения сделал он.

## Замеры (песочница, ноутбук, Docker)

| Что | Результат |
|---|---|
| перенос 10 000 пользователей (`--bulk 10000`) | 53 с — около 190 в секунду, пачки по 500 |
| первый вход перенесённого (BCrypt cost 12 + пересчёт в argon2) | 0,24–0,30 с |
| повторный вход (argon2) | около 0,025 с — как у родных пользователей |

Оценка для 1 000 000 пользователей — около полутора часов при той же скорости (линейно, не мерили). Первый вход каждого
дольше на ~0,25 с один раз.

## Как переезжать в бою

1. **Keycloak с плагином** (`bcrypt` уже в образе) и realm проекта готовы; приложения ещё на боевом сервисе.
2. **Окно обслуживания**: боевой сервис только на чтение — без регистраций и смены паролей. Повторный прогон
   добавляет новых, но **не обновляет** уже перенесённых (SKIP): смена пароля между прогоном и переключением потеряется.
3. Создать клиент `legacy-import`, секрет — из хранилища секретов в переменную окружения.
4. `--dry-run` → разобрать конфликты (номера, уже занятые в Keycloak) и строки «не переносятся».
5. Перенос; проверить отчёт (ошибок 0) и выборочно — вход старым паролем.
6. Переключить приложения на Keycloak; **удалить клиент `legacy-import`**.
7. Позже: плагин `bcrypt` держать, пока у кого-то остаётся BCrypt-хэш (кто не входил). Через N месяцев таких можно
   оставить без пароля — они войдут по коду.

## Сравнение с боевым сервисом

| | Боевой | Keycloak после переноса |
|---|---|---|
| Хэш пароля | BCrypt, cost 12 | BCrypt до первого входа, затем argon2 |
| Id пользователя | Guid | тот же Guid |
| Логин | `+79991110001` | `79991110001` (атрибут `phone` — `+7…`) |
| Роль | одна строка | роль по умолчанию + роли клиента приложения |
| Блокировка админом | `IsRestricted` + причина | `enabled=false` + атрибуты, как в админке |
| Временная блокировка после неверных паролей | `LockedUntilUtc` | не переносится — защита от перебора Keycloak |

## Как проверить

```bash
docker compose up -d --build --wait keycloak postgres redis auth-service
```

```bash
scripts/keycloak/check-migration.sh
```

Ожидается `Итого: 26 ✓, 0 ✗`. Нужен .NET SDK (инструмент запускается через `dotnet run`). Скрипт сам пересоздаёт
«боевую» базу и удаляет из Keycloak прошлый перенос, затем: перенос и отчёт; что перенеслось (Id, логин, атрибуты,
блокировка, роль, хэш `bcrypt`); вход старым паролем через страницу входа — после него хэш `argon2`, тем же паролем
снова, неверный — отказ, менеджер, кириллица, временно запертый, заблокированный; без пароля — по коду; повторный
прогон ничего не меняет и не откатывает хэш. Ключевые проверки подтверждены поломками инструмента (хэш помечен не
bcrypt, нет роли по умолчанию, перезапись вместо пропуска).

Плагин — юнит-тестами при сборке образа Keycloak (`BcryptHashTest`: хэши BCrypt.Net, 72 байта, битые хэши);
сопоставление и разбор ответа Keycloak — `LegacyImportTests` (`dotnet test`).

Вручную: `scripts/legacy/seed-legacy.sh`, затем

```bash
DOTNET_ENVIRONMENT=Development dotnet run --project src/AuthService.LegacyImport -- --dry-run
```

## Грабли

- **Обычное создание пользователя не сохраняет Id** (`POST /users` с `id` — новый Id). Сохраняет только
  `partialImport`, а ему нужно `manage-realm` — отсюда отдельный временный клиент.
- **Импорт не выдаёт роль по умолчанию**: перенесённые покупатели остались без `customer` (токен без ролей и прав).
  Нашлось вживую, исправлено явной `default-roles-sandbox`.
- **`OVERWRITE` удаляет существующего пользователя.** Мутант с перезаписью заменил тестового покупателя песочницы
  79990000001 пользователем из «боевой» базы (новый Id, пароль) — восстановлен из realm JSON с прежним Id. В бою —
  только `SKIP`.
- **Пачка падает целиком**, если Id уже занят под другим логином («Duplicate resource error», 409) — повтор по одному.
- **Перехэш — в argon2, не PBKDF2**: в Keycloak 26 алгоритм по умолчанию — argon2.
- **Конфиг консоли** искался в текущей папке (`dotnet run --project` из корня) — путь к настройкам — папка сборки.

## Ограничения (для выводов)

- **Широкое право на время переезда**: `manage-realm` у клиента `legacy-import`; удалять сразу после.
- **Нужно окно без записи** в боевой сервис: повторный прогон не обновляет перенесённых (смена пароля потеряется).
- **Плагин `bcrypt` живёт, пока есть непереехавшие хэши** — это свой код в Keycloak (риск при обновлениях Keycloak
  меньше, чем у аутентификаторов: публичный SPI `PasswordHashProvider`).
- **Сессии и refresh-токены боевого сервиса не переносятся** — после переключения все входят заново.
- **Временные блокировки и счётчики неудачных входов** не переносятся.
- **Роли без пары в Keycloak** (courier) переносятся покупателем с пометкой — решение за админом.
- **Почта** в боевом сервисе отсутствует — у перенесённых её нет; вход и сброс пароля — по телефону и коду.
