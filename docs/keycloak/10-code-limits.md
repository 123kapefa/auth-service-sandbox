# Этап 10.1. Защита от накрутки кодов

**Статус:** ✅ готово · **Задача:** [#129](https://github.com/123kapefa/auth-service-sandbox/issues/129) (этап 10 — [#128](https://github.com/123kapefa/auth-service-sandbox/issues/128))

Код по SMS стоит денег, поэтому его можно «накручивать»: слать коды на чужие номера или на свои платные (SMS-фрод).
Плагин входа по коду теперь проверяет каждую отправку. Пауза и блокировка после 5 неверных вводов — как раньше
([05](05-code-login.md)).

## Что проверяется перед отправкой

По порядку; первое сработавшее — отказ, код не уходит и не сохраняется.

| Проверка | По умолчанию | Сообщение на экране кода |
|---|---|---|
| Пауза перед повтором на номер — растёт | 60 с → 2 мин → 5 мин → 15 мин (по числу отправок за час) | «Код уже отправлен. Новый можно запросить через N с.» |
| Страна номера | только +7 | «На номера этой страны коды не отправляем. Войдите по почте.» |
| Отправок на номер (почту) | 5 в час, 10 в сутки | «Слишком много запросов кода. Попробуйте через N мин.» |
| Отправок с IP | 10 в час | то же |
| Отправок на диапазон номеров (первые 7 цифр) | 20 в час | то же |
| Капча | после 2 отправок за час с IP или на номер | «Подтвердите, что вы не робот, и запросите код ещё раз.» |
| Дневной бюджет проекта (выключает только SMS) | 1000 ₽, SMS — 4 ₽, звонок — 1 ₽ | «Сейчас не можем отправить SMS. Войдите по почте или с ключом доступа.» |

- Лимиты срабатывают и с капчей: капча не открывает отправку сверх лимита. Пока лимит выбран, капча тоже нужна
  (порог капчи ниже лимитов).
- Все окна скользящие: «за час» — за последние 60 минут.
- Почта бесплатна: бюджет её не трогает, а лимиты на номер и IP действуют (письма тоже можно накручивать).
- Звонки ([10.2](10-phone-code.md)) в расход считаются, но бюджет их не выключает: когда он кончился, код на телефон
  по-прежнему приходит звонком, отказ — только на «Прислать SMS».
- Сутки бюджета — по Москве: в полночь расход обнуляется, SMS снова уходят.
- Счётчики — в общем хранилище Keycloak (SingleUseObjectProvider), там же, где состояние кода: в кластере общие для
  всех узлов. Чтение и запись не атомарны — при одновременных запросах лимит может пропустить лишнюю отправку.

## Капча

Экран кода получает `captchaRequired` ("true" — следующий код уйдёт только с капчей) и `captchaSiteKey`. Браузер
присылает ответ капчи полем `smart-token` вместе с «Отправить код ещё раз» (или «Войти по коду»); плагин проверяет его
у Яндекс SmartCaptcha (`POST https://smartcaptcha.yandexcloud.net/validate`). Сбой сервиса капчи считается пройденной
капчей (так советует Яндекс; лимиты при этом действуют). Код не ушёл без капчи — экран получает `captchaStep=true`, и
тема показывает «Проверку» с виджетом ([10.8](10-login-theme.md#капча), там же — CSP для виджета).

- Бой: `KC_SPI_AUTHENTICATOR__PLATFORM_CODE_LOGIN__CAPTCHA_SERVER_KEY` и `…__CAPTCHA_SITE_KEY` (в `deploy/compose.yaml`
  — из `AUTH_SMARTCAPTCHA_SERVER_KEY` и `AUTH_SMARTCAPTCHA_SITE_KEY`). Без ключа капчу пройти нельзя: после порога код
  не уходит, в логе при старте — предупреждение.
- Стенд: `…__CAPTCHA_STUB=true` — заглушка, проходит токен `sandbox-captcha-ok`; ключ сайта — `sandbox-stub`, тема
  рисует вместо виджета галочку «Я не робот».

## Оповещения и метрики

- Расход дошёл до 80 % бюджета и бюджет исчерпан — по одному разу в сутки на проект: строка `WARN [CODE BUDGET] …` в
  логе Keycloak, метрика `platform_code_budget_alerts_total{percent="80"|"100"}` и письмо админам проекта.
- Письмо (`BudgetAlerts`, шаблон `platform-code-budget.ftl` темы писем, общий каркас писем): сколько ушло из дневного
  бюджета и что будет дальше — при 80 % «когда кончится, SMS выключатся до полуночи», при 100 % «SMS выключены, звонки и
  почта работают». Админ проекта — у кого право `sign-in.manage` в `auth-api` (в песочнице `sandbox-api`): ролью
  `admin`, другой составной ролью или группой. Каждому — на его языке, в оформлении проекта; без почты, выключенным и
  служебным учёткам не пишем; больше 50 адресов за раз — нет. Письма уходят в том же запросе кода, по одному; ошибка
  почты — строка в логе, код всё равно уходит.
- «Раз в сутки» — отметка о пороге рядом с расходом за сутки (общее хранилище Keycloak). Бюджет исчерпали, минуя 80 %
  (бюджет меньше цены кода), — придёт только письмо о 100 %.
- Метрики Prometheus (`KC_METRICS_ENABLED=true`, `/metrics` на порту управления 9000), у всех — метка `realm`:

| Метрика | Что |
|---|---|
| `platform_code_sent_total{channel}` | отправлено кодов (CALL, SMS, EMAIL) |
| `platform_code_verified_total{channel}` | введено верно |
| `platform_code_cost_kopecks_total{channel}` | расход, копейки |
| `platform_code_refused_total{reason}` | не отправлено: `limit`, `captcha`, `country`, `budget` |

Падение доли введённых кодов — главный признак накрутки (коды уходят, но их никто не вводит). Правило Prometheus:

```yaml
- alert: PlatformCodeConversionDrop
  # Доля введённых SMS-кодов за час упала ниже 30 % при заметном числе отправок.
  expr: |
    sum by (realm) (increase(platform_code_verified_total{channel="SMS"}[1h]))
      / sum by (realm) (increase(platform_code_sent_total{channel="SMS"}[1h])) < 0.3
    and sum by (realm) (increase(platform_code_sent_total{channel="SMS"}[1h])) > 20
  for: 15m
```

## Настройки

Значения по умолчанию — в коде (`CodeLimitPolicy.DEFAULTS`). Каждое можно переопределить:

1. у проекта — атрибут realm `platform.codes.<ключ>` (их пишет API админки — [10.7](10-code-settings.md); пустое значение — «не задано»);
2. для всего сервера — переменная `KC_SPI_AUTHENTICATOR__PLATFORM_CODE_LOGIN__<КЛЮЧ>`;
3. иначе — по умолчанию.

Ключи: `cooldowns` (секунды через запятую), `target-per-hour`, `target-per-day`, `ip-per-hour`, `range-per-hour`,
`range-digits`, `captcha-after`, `countries` (коды стран через запятую: `7,375`), `daily-budget`, `sms-cost` и `call-cost` (копейки;
бюджет 0 — без бюджета), `budget-alert-percent`, `zone`. Неверное значение в настройках сервера не даёт Keycloak
стартовать; в атрибуте проекта — код не отправляется.

На стенде (`compose.yaml`) лимиты ослаблены, бюджет выключен: скрипты проверки шлют коды с одного IP на одни и те же
номера. IP за прокси берётся из `X-Forwarded-For` (`KC_PROXY_HEADERS`; на стенде включено, чтобы проверять лимиты «с
IP» с разных адресов).

## Проверка

```bash
scripts/keycloak/check-code-limits.sh
```

Ожидается `Итого: 40 ✓, 0 ✗`. Скрипт на время проверки задаёт свои настройки атрибутами realm (короткие паузы, лимит 3
вместо 5…) и снимает их в конце; у каждого раздела — свой IP. Проверяет: растущую паузу, капчу (без неё и с неверной —
отказ), лимиты на номер (и с капчей, и с другого IP), с IP, на диапазон, страну, исчерпанный бюджет (звонок идёт, SMS — отказ, почта —
работает), метрики. Правила без Keycloak — юнит-тесты `CodeLimitsTest`.

Письма админам о бюджете — отдельно (`Итого: 14 ✓, 0 ✗`, письма — в Mailpit стенда):

```bash
scripts/keycloak/check-budget-alerts.sh
```

Бюджет на время проверки — «расход за сегодня + 1,20 ₽»: звонок переводит за 80 %, «Прислать SMS» — за 100 %. Проверяет:
оба письма пришли каждому админу и по одному, повторно в те же сутки писем нет, покупателю и менеджеру — ничего. Если
бюджет в эти сутки уже исчерпали раньше (например, `check-code-limits.sh`), письма о 80 % не будет — скрипт попросит
перезапустить Keycloak. Тексты письма — юнит-тесты `BudgetAlertsTest`.

Стенд, поднятый до 10.1: `docker compose up -d --build --wait keycloak` (новые переменные в `compose.yaml`; realm менять
не нужно).
