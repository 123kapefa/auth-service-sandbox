# Этап 10.8. Тема входа по макетам

**Статус:** ✅ готово · **Задача:** [#136](https://github.com/123kapefa/auth-service-sandbox/issues/136) (этап 10 — [#128](https://github.com/123kapefa/auth-service-sandbox/issues/128))

Страницы входа приведены к макетам этапа 10 (экраны 05–06, 09–13, 16–20; набор компонентов — доска Kit). Логика
входа — та же, что в 10.1–10.6: меняется вид, плюс капча на странице и пара атрибутов плагина для темы.

## Что поменялось в плагине

- **`loginKinds`** у `login.ftl` — какими логинами можно войти в проект (`phone`, `email`): по ним — подпись поля на
  шаге 1. Считается из способов входа проекта (10.7): способ «Телефон» или «Почта» выключен — такой логин не
  предлагаем.
- **`captchaStep`** у экрана кода — код не ушёл, потому что нужна капча: тема показывает экран «Проверка». Раньше на
  отказ был только текст ошибки.
- **Первый экран кода на телефон показывает звонок.** Пока код ещё не отправлялся (отказ лимита, капча), способ
  доставки на экране — тот, которым код уйдёт (`choose(...)`), а не пустой.
- **Заглушка капчи стенда** отдаёт ключ сайта `sandbox-stub`: тема рисует вместо виджета галочку «Я не робот» с
  пометкой «Заглушка стенда», ответ — `smart-token=sandbox-captcha-ok`.

## Капча

Бой: виджет Яндекс SmartCaptcha (`https://smartcaptcha.yandexcloud.net/captcha.js`, `smartCaptcha.render(...)`)
в форме отправки; ответ уходит полем `smart-token`. Виджет — в iframe, поэтому realm разрешает его в CSP
(`browserSecurityHeaders.contentSecurityPolicy` в `infra/keycloak/realm/sandbox-realm.json`):

```
frame-src 'self' https://smartcaptcha.yandexcloud.net; frame-ancestors 'self'; object-src 'none';
```

Новый стенд берёт это из файла realm. **Старый стенд** — вручную: админка Keycloak → Realm settings → Security
defenses → Headers → Content-Security-Policy. Заглушке стенда CSP не нужен.

## Решения по умолчанию

- На шаге пароля — одна кнопка кода, по введённому логину («Звонок» для номера, «Код на почту» для почты), а не обе, как
  на макете: обе кнопки выдавали бы, есть ли у человека почта или номер (правило неразличимости из 10.4).
- «Выбрать другой способ» на экране кода начинает вход заново (шаг 1): отдельного возврата к способам у плагина нет.
- Номер, с которого звонят, заранее не известен — на экране звонка картинка общая: `••• •••-XX XX`.
- На смене номера кнопка — «Получить код» (звонок или SMS выбирает плагин).
- Коды восстановления 2FA — ссылка каркаса «Другой способ входа».

## Проверка

```bash
cd login-theme && npm run lint && npm run type-check && npm test   # 49 тестов страниц
cd infra/keycloak/providers/code-login && mvn -q test                 # плагин
```

На стенде (образ Keycloak пересобран) — прежние проверки входа: `check-code-login`, `check-two-step-login`,
`check-phone-change`, `check-code-limits`, `check-passkey-offer`, `check-project-sign-in`, `check-sign-in-methods`,
`check-login`, `check-login-methods`, `check-external-login`, `check-phone-code`, `check-code-settings` (все зелёные).
Посмотреть экраны без Keycloak: `npm run dev`, затем `?page=platform-code-login.ftl&overrides={"captchaStep":"true"}` —
параметр `overrides` (JSON) дополняет макет страницы.
