# Этап 10.6. Предложение ключа доступа после входа по коду

**Статус:** ✅ готово (оформление — 10.8) · **Задача:** [#134](https://github.com/123kapefa/auth-service-sandbox/issues/134) (этап 10 — [#128](https://github.com/123kapefa/auth-service-sandbox/issues/128))

Каждый вход по коду — звонок, SMS или письмо. Ключ доступа бесплатный и надёжнее: его нельзя украсть вместе с номером.
Поэтому после входа по коду предлагаем завести ключ, чтобы в следующий раз войти без кода.

## Как выглядит

1. Человек вошёл по коду (звонок, SMS или письмо; с 2FA — после кода приложения).
2. **«Входите без кода»**: «Добавьте ключ доступа — в следующий раз войдёте по Face ID, отпечатку или PIN этого
   устройства…». Кнопки «Добавить ключ доступа» и «Не сейчас», внизу — «Спросим снова через 30 дней. Добавить можно и
   в кабинете.»
3. «Добавить ключ доступа» сразу открывает окно браузера (Face ID, отпечаток, PIN). Ключ заведён, называется «Ключ
   доступа», человек идёт дальше — в приложение, откуда начинал вход.
4. Окно закрыли или браузер не умеет ключи — «Не получилось добавить ключ…»: «Попробовать ещё раз» или «Не сейчас».
5. «Не сейчас» — дальше без ключа; 30 дней после этого не спрашиваем.

Не предлагаем:

- когда ключ доступа у человека уже есть;
- 30 дней после «Не сейчас»;
- после входа паролем, ключом, через Госуслуги или Яндекс ID и когда сессия уже есть (вход без формы);
- в действиях из кабинета (смена номера, ключа, почты — `kc_action`);
- если ключи доступа в проекте выключены.

## Как устроено

- Плагин: действие Keycloak `platform-passkey-offer` (`PasskeyOfferAction`). Вход по коду (`CodeLoginAuthenticator`)
  ставит заметку входа; действие по ней решает, предлагать ли (`PasskeyOfferRules`, без Keycloak, с тестами), и
  добавляет себя только в этот вход — не в аккаунт человека.
- Сам ключ заводит стандартное действие Keycloak `webauthn-register-passwordless`: его страницы
  (`webauthn-register.ftl`, `webauthn-error.ftl`) получают атрибут `platformPasskeyOffer`, и тема рисует вместо них
  экран предложения (`PasskeyRegister.tsx`). Добавление ключа из кабинета — та же страница в том же стиле: заголовок
  «Ключ доступа», галочка «Выполнить выход на других устройствах», «Добавить ключ доступа» и «Отмена».
- «Не сейчас» — атрибут `passkey_offer_skipped_at` (время, ISO). Он вне профиля: сам человек его не изменит.
- Ключ заведён — Keycloak пишет в журнал событие `UPDATE_CREDENTIAL` (`webauthn-passwordless`).

## Старый стенд

Realm импортируется только в пустую базу, поэтому на стенде, поднятом до 10.6:

```bash
docker compose up -d --build --wait keycloak                # новый плагин и тема
python3 scripts/project/enable-passkey-offer.py sandbox     # включить действие в realm
```

## Проверка

```bash
scripts/keycloak/check-passkey-offer.sh
```

Ожидается `Итого: 12 ✓, 0 ✗`: после первого входа по коду — предложение; окно ключа не вышло — «Не получилось»,
«Попробовать ещё раз» — снова предложение; «Не сейчас» — в сервис, время записано; через день и через 29 дней — без
предложения, через 30 — снова; вход паролем — без предложения. Сам ключ curl не заведёт: «Добавить ключ доступа»
проверено в браузере с виртуальным ключом (Playwright) — ключ заведён, человек вернулся в кабинет, следующий вход по
коду — без предложения.

Другие проверки, где входят по коду (`lib.sh`: `code_submit`, `check-two-step-login.sh`, `check-shop.sh`,
`check-code-login.sh`), на предложении нажимают «Не сейчас».
