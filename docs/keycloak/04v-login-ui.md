# Этап 4в. Свой интерфейс входа (Keycloakify)

**Статус:** ✅ готово · **Ветка:** `stage-4v/login-ui` · **Задача:** [#60](https://github.com/123kapefa/auth-service-sandbox/issues/60)
· закрывает бэклог [#56](https://github.com/123kapefa/auth-service-sandbox/issues/56)

## Цель

Страницы входа и письма Keycloak — в стиле своей админки, а не стандартной темы `keycloak.v2`. Пользователь
не должен видеть «чужой» интерфейс ни на одном шаге: вход, код, 2FA, сброс пароля, ошибки, письма.

Решения (2026-10-02):

- оформление — **как админка**: Tailwind, те же цвета, светлая и тёмная тема по системе;
- **одна тема** `sandbox` на проект; варианты для приложений (свой логотип и цвета) — потом;
- **все письма в теме**, включая письмо с кодом входа из плагина.

## Как устроено

### Тема входа (login-theme/)

Keycloakify 11: страницы — React-компоненты, при сборке превращаются в jar темы Keycloak. Стек как у админки
(Vite, React 19, TypeScript, Tailwind 4, Vitest), но без FSD — это набор страниц, а не приложение. Подробно —
`login-theme/CLAUDE.md`.

| Что | Как |
|---|---|
| Свои страницы | `login.ftl` — телефон или почта и пароль, «Войти по коду», «Войти с ключом доступа»; `sandbox-code-login.ftl` — экран кода плагина |
| Остальные страницы Keycloak | стандартные компоненты Keycloakify в нашем каркасе (`Template.tsx`) с нашими классами (`classes.ts`): 2FA (ввод и настройка), коды восстановления, ключ доступа, сброс и новый пароль, выбор способа входа, «Страница устарела», информация и ошибки |
| Тексты | `i18n.ts`: тексты плагина (ключи `form.setError(...)` сервера), тексты realm, которых нет у страниц в браузере, и около 40 ключей Keycloak без русского перевода |
| Атрибуты плагина | приходят в `kcContext` страницы сами (`codeChannel`, `codeTarget`, `codeResendAfter`, `codeLength`) — нужны только типы |
| Просмотр без Keycloak | `npm run dev` → `http://localhost:5174/?page=login.ftl` (любая страница — на макетах `mocks.ts`) |

**Страница входа.** Номер показывается маской `+7 (999) 000-00-01` (8 и 10 цифр тоже приводятся к `+7`), а на
сервер уходит цифрами — скрытым полем `username`; почта — как есть. Ошибка «неверный логин или пароль» — у полей,
без общей плашки. Кнопки блокируются на время отправки.

**Экран кода.** Отсчёт до повтора (`codeResendAfter`), поле только для цифр длиной из политики плагина
(`codeLength`), код отправляется сам, когда набраны все цифры. Повтор — отдельной формой.

### Тема писем (login-theme/src/email/)

Шаблоны FreeMarker без React (Keycloakify кладёт их в тот же jar как есть), `emailTheme: sandbox` в realm.

| Письмо | Шаблон | Когда |
|---|---|---|
| Сброс пароля | `password-reset.ftl` | «Забыли пароль?» на странице входа |
| Обновите учётную запись | `executeActions.ftl` | админка: «Сбросить пароль» (`execute-actions-email`) |
| Подтвердите почту | `email-verification.ftl` | подтверждение адреса |
| Код для входа | `sandbox-login-code.ftl` | вход по коду на почту (плагин) |
| Остальные (уведомления, приглашения) | шаблоны Keycloak | в нашем каркасе `template.ftl` |

Каркас — таблицы и стили в атрибутах: почтовые программы не читают `<style>` и плохо понимают flex. Под кнопкой —
та же ссылка текстом. У каждого письма — текстовый вариант (`text/`).

**Письмо с кодом.** Стандартный `EmailTemplateProvider` Keycloak шлёт письма пользователю, а код неизвестной почте
уходит до создания пользователя. Поэтому плагин (`EmailCodeSender`) сам обрабатывает шаблон темы писем через
`FreeMarkerProvider` и отправляет через `EmailSenderProvider`, на языке страницы входа. Тексты — в
`messages_{ru,en}.properties` темы писем, а не в Java.

### Сборка

`infra/keycloak/Dockerfile`, стадия `node:22-alpine` с Java и Maven: `npm ci`, `npm run build-keycloak-theme` →
`sandbox-login-theme.jar` в `/opt/keycloak/providers/`. Node, Java и Maven на машине не нужны. Старая тема
`infra/keycloak/themes/sandbox` (FreeMarker поверх `keycloak.v2`, этапы 3а и 5) удалена.

## Сравнение с боевым сервисом

| | Боевой | Песочница |
|---|---|---|
| Страницы входа | свои, Razor Pages + htmx + Alpine, без сборки фронтенда | тема Keycloak на React (Keycloakify), собирается в образе Keycloak |
| Маска телефона, таймер кода | Alpine | React |
| Работа без JavaScript | да (progressive enhancement) | нет: страницы рисует React |
| Письма | — (код — SMS) | тема писем Keycloak: сброс, ссылка из админки, подтверждение, код |
| Тёмная тема | — | по системе |

## Как проверить

```bash
docker compose up -d --build --wait keycloak redis mailpit auth-service
```

Скрипты проходят вход через страницы новой темы — формы и тексты читают из `kcContext` в HTML
(`scripts/keycloak/kc_context.py`):

```bash
scripts/keycloak/check-stand.sh && scripts/keycloak/check-login.sh && scripts/keycloak/check-login-methods.sh && scripts/keycloak/check-code-login.sh
```

Что именно про тему: страница входа — тема `sandbox`; экран кода знает длину кода и паузу до повтора; письмо с
кодом — HTML по шаблону темы с этим кодом; письмо сброса — по нашему шаблону; ссылка из админки — письмо
«Обновите учётную запись» (`check-admin.sh`). Без темы писем у realm эти проверки падают.

Тема — тестами Vitest (маска телефона, логин на сервер, ошибки у полей, экран кода, стандартные страницы по-русски):

```bash
cd login-theme && npm ci && npm run lint && npm run type-check && npm test
```

Глазами: страницы — `npm run dev` в `login-theme/` (макеты) или http://localhost:8080/auth/login (стенд); письма —
Mailpit, http://localhost:8025.

## Грабли

- **Скрипты не видели форм.** Страница Keycloakify — пустой `<div>` и `kcContext` в JavaScript (с комментариями,
  висячими запятыми, функциями). Скрипты читают его разборщиком `kc_context.py`: страница — по `templateName`,
  адрес формы — `url.loginAction`, ошибки — `message.summary`.
- **Показ пароля падал.** Хук `useIsPasswordRevealed` ищет поле в DOM сразу, а каркас рисует содержимое не в первый
  проход — хук вынесен в компонент поля.
- **Номер затирался.** Контролируемое поле с приведением к цифрам ломало ввод — видимое поле без имени, на сервер —
  скрытое `username`.
- **Тексты realm не видны странице.** `localizationTexts` realm Keycloakify в браузер не передаёт — нужные
  продублированы в `i18n.ts`. В `withCustomTranslations` — одинаковый набор ключей во всех языках.
- **Английские подписи.** У части ключей Keycloak нет русского перевода (2FA, коды восстановления, названия способов
  входа) — добавлены свои.
- **Двойная нумерация** кодов восстановления: общий стиль списков `#kc-content ol` наложился на номера в тексте.
- **`kcFormSettingClass` с flex** сужал кнопку — сетка.
- **Защита от перебора и заблокированный.** Каждая попытка заблокированного тестового пользователя — неудача; после
  многих прогонов подряд его временно запирало, и Keycloak отвечал «Invalid user credentials» вместо
  «Account disabled». `check-stand.sh` сбрасывает счётчик перед проверкой.
- **`FreeMarkerProvider`** в Keycloak 26 — в пакете `org.keycloak.theme.freemarker`, а не `org.keycloak.theme`.

## Ограничения (для выводов)

- **Без JavaScript не войти**: страницы рисует React. Боевой вход работает и без него.
- **Jar темы ~2,3 МБ** (React и стили); первая сборка образа Keycloak дольше — нужен Node.
- **Обновление Keycloak** может потребовать обновления Keycloakify (типы `kcContext` страниц).
- **Стандартные страницы** — компоненты Keycloakify: разметка их, оформление — наше через классы и стили
  `#kc-content`. Свои версии — только для страницы входа и экрана кода.
- **Письмо с кодом зависит от темы писем**: без `emailTheme: sandbox` код на почту не уйдёт (экран покажет «Не
  удалось отправить код»).
- **Одна тема**: оформление под приложение (логотип, цвета по `client_id`) — следующий шаг, не сделан.
- **Нет E2E-тестов в браузере** — Vitest на страницы, скрипты на путь через стенд, просмотр глазами.
