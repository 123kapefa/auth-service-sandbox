# Журнал трений встраивания

Что мешало, когда сервис входа встраивали как чужой проект. Каждое трение — что случилось, как обошли и что
предлагаем. Исправления — шаг 6а.6 (кроме отмеченных «исправлено»). Этап — [06a-embedding.md](06a-embedding.md).

## 6а.4 Новый проект: магазин «Заказы» + «Уведомления»

Проект «Демо-магазин» (realm `demo-shop`), сервисы — `samples/shop`, подключены пакетами `Platform.*` из фида, как
подключил бы их чужой проект. Проверка — `scripts/keycloak/check-shop.sh`.

| # | Трение | Как обошли | Предложение | Вес |
|---|---|---|---|---|
| 1 | **Новый покупатель приходил в «Заказы» без прав.** Права в токене — по режиму в приложении (`active_mode.orders`), а его ставит только смена ролей в админке. Покупатель, вошедший по коду, режима в «Заказах» не имел — `permissions: []`, все запросы 403 | — | **Исправлено:** режим не выбран — роль по умолчанию (маппер токена и проверка доступа по ключу) | блокер |
| 2 | **Токен по ключу адресован только сервису входа** (`aud=auth-api`). «Уведомлениям» пришлось принимать адресата сервиса входа; токен *человека* из сервиса входа проекта проходит подпись и адресата — отсекает его только `RequireService` | `Audience: auth-api` + `RequireService()` | адресат токена ключа — сервисы проекта (своя область), в пакете — несколько адресатов (`Audiences`) | важно |
| 3 | **Права ключа есть только в сервисе входа** (`service.users.read`, `service.access.check`). Право «присылать уведомления» ключу «Заказов» не выдать — «Уведомления» держат свой список `client_id` в настройках | `Notifications:AllowedServices` | права ключа на приложения проекта: роли клиента приложения у служебной учётки (маппер их уже читает) | важно |
| 4 | **Права приложения кодом не объявить.** Сервис входа заводит свои права при старте, а «Заказы» — нет: права и роли заводит админ руками или скрипт (`setup.sh`). Опечатка в праве — молчаливый 403 | скрипт через API админки | **Исправлено:** `AddAppCatalog` в пакете — сервис при старте объявляет права и роли своим ключом (право `service.catalog.declare`); права из кода в админке не удалить, роли заводятся один раз | важно |
| 5 | **Режим в другом приложении человеку не переключить.** `POST /auth/mode` — только для приложения сервиса входа; страница «Заказов» в сервис входа и не попадёт (её токен — `aud=orders`). Сотрудник с ролями customer и manager работает как customer | атрибут `active_mode.orders` мастер-админкой Keycloak | `POST /auth/mode { activeMode, app }` и переключатель в кабинете | важно |
| 6 | **Перевыпуск ключа = остановка вызовов до перезапуска.** Старый секрет перестаёт действовать сразу, новый сервис берёт только из окружения при старте: между перевыпуском и перезапуском «Заказы» уведомлений не шлют | перезапуск с новым секретом | перевыпуск с перекрытием (старый секрет действует N минут) или секрет из файла с перечитыванием | средне |
| 7 | **Пакет по умолчанию читает cookie `accessToken`.** Чужому сервису это неожиданно: на localhost браузер несёт cookie сервиса входа на любой порт | `AccessTokenCookie: ""` | по умолчанию — только заголовок; cookie — явной настройкой | средне |
| 8 | **Вход в приложение — PKCE руками.** Cookie сервиса входа (BFF) «Заказам» не годятся (другой адресат, другой хост в бою); готового модуля входа для страницы нет — 60 строк на странице | своя страница (`Orders/wwwroot`) | маленький JS-модуль входа в поставке или BFF-вход для приложений | средне |
| 9 | **Одна версия пакетов (0.1.0).** Перепакованный пакет с той же версией потребитель не видит — берёт старый из кэша NuGet | очистка `~/.nuget/packages/platform.*` | `pack.sh` с суффиксом сборки для локального фида (`0.1.0-dev.N`) | средне |
| 10 | **Много адресов в настройках.** У каждого сервиса: Authority (внешний, для `iss`), MetadataAddress и TokenEndpoint (внутри сети), адрес сервиса входа — 4 адреса на одну систему | — | один «внутренний адрес Keycloak» в пакете, остальное выводится | мелочь |
| 11 | **Клиент API тянет наш стиль ошибок.** `Platform.AuthService.Client` возвращает `Result<T, Error>` (CSharpFunctionalExtensions, `Platform.SharedKernel`) — чужой проект получает их зависимостью | — | оставить (стандарт платформы) или исключения/свой результат в клиенте | мелочь |
| 12 | **Правила сборки песочницы цепляются к примерам.** `Directory.Build.props` и `Directory.Packages.props` из корня действуют на любой проект ниже по дереву | свои файлы в `samples/shop` | — (в отдельном репозитории проекта не мешает) | мелочь |

Что прошло гладко: вход через страницы проекта (тема, название, вход по коду) для приложения с `--web`; проверка
токенов, прав и мгновенного отзыва в чужом сервисе — три строки в `Program.cs`; токен по ключу с повтором на 401;
чужие токены (другой проект, другой адресат, человек вместо сервиса) отклоняются без своего кода.
