# Этап 10.3. Способы входа: человек выключает ненужные

**Статус:** ✅ готово (API и плагин; кабинет — [10.9](10-account.md), админка — [10.10](10-admin.md)) · **Задача:** [#131](https://github.com/123kapefa/auth-service-sandbox/issues/131) (этап 10 — [#128](https://github.com/123kapefa/auth-service-sandbox/issues/128))

Человек сам решает, как в его аккаунт можно войти: пароль, код на телефон и код на почту можно выключить, как у
Microsoft. Кто перешёл на ключ доступа, выключает и пароль, и код на телефон: утёкший пароль и старый номер телефона
больше не открывают аккаунт.

## Что значит «выключен»

Выключенный способ не пускает никого:

| Способ | Что происходит |
|---|---|
| Пароль | форма входа отвечает «Неправильное имя пользователя или пароль» — так же, как на неверный пароль, даже если пароль верный; токен по паролю (direct grant, клиенты отладки) — `invalid_grant`; привязка Яндекс ID или Госуслуг паролем — тоже нет |
| «Забыли пароль» при выключенном пароле | страница та же («Вы должны получить письмо…»), но письма нет: ссылка включила бы пароль обратно |
| Код на телефон / на почту | экран «Вам звонят…» / «Отправили код письмом…» — как обычно, но звонка, SMS и письма нет, и никакой код не подходит |

По ответам нельзя понять, что выключено и есть ли аккаунт. В журнале событий Keycloak у такого отказа — `reason`
(`password_disabled`, `method_disabled`), в метриках кодов — отказ `method-disabled`.

Ключ доступа не выключается, а удаляется; Яндекс ID и Госуслуги — отвязываются. Приложение-аутентификатор — второй
шаг после пароля или кода, как раньше.

## Правила

1. Хотя бы один способ входа остаётся всегда (`last_method`).
2. Пароль и код на телефон выключаются, только если есть ключ доступа или приложение-аутентификатор
   (`needs_passkey_or_authenticator`).
3. Изменить можно, только если вошли меньше 5 минут назад (`auth.reauthentication_required` — войти заново:
   `/auth/login?reauth=true`).
4. Если есть приложение-аутентификатор, нужны коды восстановления (`recovery_codes_required`). Без аутентификатора
   они не требуются: у Keycloak коды восстановления — второй шаг входа, и одни они спрашивались бы при каждом входе.
5. О каждом изменении — письмо (если почты нет — SMS) и запись в журнал.
6. При выключении — «выйти на других устройствах» (по умолчанию да).
7. Админ не выключает способы за человека — только возвращает всё по умолчанию.

**Страховка.** Ключ доступа или аутентификатор можно удалить и позже — на странице Keycloak, в обход правил. Поэтому
плагин применяет выключение с оглядкой: пароль и код на телефон выключены, только пока есть ключ доступа или
аутентификатор; если не осталось ни одного способа (нет ключа и внешнего входа, а всё доступное выключено) — не
выключено ничего. Так удалённый ключ возвращает пароль, а не запирает человека. Те же правила — в сервисе
(`SignInMethodRules`) и в плагине (`SignInMethods`), кабинет показывает то, что на самом деле действует.

## Где хранится

Атрибут пользователя `disabled_sign_in_methods` — способы через запятую (`password,phone-code`). Его пишет только
сервис входа (служебной учёткой, по правилам выше). Сам человек через Keycloak его не изменит: атрибута нет в профиле,
а неописанные атрибуты realm меняет только админ (`unmanagedAttributePolicy: ADMIN_EDIT`). Миграции realm не нужно.

## API

Кабинет (любой вошедший — только своё):

```
GET /me/sign-in-methods
→ { methods: [ { method: "password", available, enabled, disableBlocker }, … phone-code, email-code ],
    hasPasskey, hasAuthenticator, hasRecoveryCodes, linkedProviders: ["yandex"],
    history: [ { at, method, enabled, byAdmin }, … ],       // до 20, новые сверху
    projectDisabled: ["password", "yandex"] }               // выключено в проекте (10.7) — кабинет не показывает

PUT /me/sign-in-methods/{password | phone-code | email-code}
{ "enabled": false, "signOutOtherDevices": true }
→ то же, что GET; 409 sign_in_methods.<причина>, 403 auth.reauthentication_required, 404 — другой способ
```

`available` — способ у человека есть (пароль задан, телефон или почта указаны); `disableBlocker` — почему выключить
нельзя (`not_available`, `needs_passkey_or_authenticator`, `last_method`, `recovery_codes_required`), по нему кабинет
(10.9) объясняет, что сделать сначала. Повтор того же — 200 без письма и записи.

Админка:

- `GET /auth/admin/users/{id}/sign-in-methods` — то же для карточки пользователя (право `users.view`; менеджеру —
  только покупатели);
- `POST /auth/admin/users/{id}/sign-in-methods/reset` — вернуть способы по умолчанию (право `users.credentials.manage`,
  только админ проекта, после недавнего входа; себе — нельзя). Человеку — письмо, в журнал — `UserSignInMethodsReset`;
- `POST /auth/admin/users/{id}/password-reset` при выключенном пароле — 409 `users.password_disabled`: сначала вернуть
  способы по умолчанию.

## Уведомления и журнал

Письмо шлёт Keycloak — плагин `platform-account-notice` (`POST /realms/{realm}/platform-account-notice/users/{id}`,
токен служебной учётки с ролью `manage-users`): шаблон `platform-sign-in-methods.ftl` темы писем в оформлении проекта,
тексты — в `messages_*.properties` темы писем. Почты нет — SMS через ту же телефонию, что коды
([10.2](10-phone-code.md)). Уведомление — «по возможности»: не ушло — изменение всё равно сделано, сбой в логе сервиса.

Журнал — таблица действий сервиса: `UserSignInMethodChanged` (сделал сам человек — исполнитель совпадает с
пользователем) и `UserSignInMethodsReset` (админ). Админка видит их в журнале, кабинет — в `history`.

## Проверка

```bash
scripts/keycloak/check-sign-in-methods.sh
```

Ожидается `Итого: 43 ✓, 0 ✗`: выключить пароль (атрибут, письмо, другое устройство вышло, история); верный пароль —
тот же отказ, что неверный, токена по паролю нет; «Забыли пароль» без письма; выключенные коды на почту и телефон —
экран как обычно, но ничего не уходит; админ видит способы, не шлёт ссылку на пароль, возвращает по умолчанию
(письмо, история), после этого пароль и «Забыли пароль» снова работают; без ключа доступа пароль снова включён и
выключить его нельзя.

Стенд, поднятый до 10.3: `docker compose up -d --build --wait` (новый плагин, шаблон письма и сервис).
