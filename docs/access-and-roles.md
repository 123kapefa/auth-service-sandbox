# Роли, права и доступ

Как устроен доступ к приложениям проекта и как им управлять. Подключение сервисов — [embedding-guide.md](embedding-guide.md).

## Как это работает

- У каждого **приложения** свои **права** (`orders.view`) и **роли** (`customer`, `manager`) — наборы прав.
- У человека может быть несколько ролей. Работает он в одной — это **режим**. Права токена — права режима: админ в режиме
  покупателя получает права покупателя.
- Роль по умолчанию (`customer`) есть у всех, снять её нельзя.
- Права и роли можно менять из админки без нового релиза и без перелогина.

Права объявляет код приложения: сервис при старте сообщает свои права и роли ключом (`AddAppCatalog` в пакете
`Platform.Authentication`). Объявленные кодом права из админки не удалить. Свои права и роли админ добавляет в админке.

## Токен

Access-токен живёт 15 минут. Сервис проверяет подпись локально, обращаться к серверу входа на каждый запрос не нужно.

| Claim | Что |
|---|---|
| `sub` | id человека |
| `role`, `available_roles` | его роли в приложении |
| `active_mode` | режим |
| `permissions` | права режима |
| `phone` | телефон |

В эндпоинте: `.RequireAuthorization(AuthPolicies.ADMIN_ONLY)` (роль + режим) или
`.RequirePermissions("orders.view")` (право). Без токена — 401, без права — 403.

## Что происходит при изменении доступа

| Действие | Что видит человек |
|---|---|
| Заблокировали, закрыли доступ к приложению, «выйти везде», завершили сессию | токен перестаёт приниматься **сразу** (401), нужно войти заново |
| Выдали или сняли роль, изменили состав роли | 401 `access_changed`; клиент вызывает `POST /auth/refresh`, получает новый токен и список изменений (`changes`) и повторяет запрос без перелогина; демо-страница и админка показывают плашку «Ваш доступ изменился» |

Это работает во всех сервисах проекта, подключённых пакетами `Platform.Authentication` и `Platform.Authentication.Redis`.

## Админы

| Действие | Админ проекта | Админ приложения |
|---|---|---|
| Видеть людей | всех в проекте | с ролью в своём приложении; остальных — по точному телефону или почте |
| Блокировать аккаунт целиком | да | нет |
| Закрыть доступ к приложению | к любому | к своему |
| Роли людей | во всех приложениях | в своём |
| Роли и права приложения | во всех | в своём |
| Сброс пароля и 2FA, «выйти везде» | да | нет |
| Журнал | весь проект | своё приложение |

**Админ проекта** — тот, кто работает в режиме `admin` приложения сервиса входа. **Админ приложения** — тот, у кого среди
ролей *в самом приложении* есть права управления им (`roles.manage`, `users.roles.manage`).

Менеджер работает только с покупателями (сотрудников не видит). Правила для всех:

- себя нельзя заблокировать, сменить себе роль, закрыть себе доступ;
- выдать роль с управлением ролями можно только после недавнего входа (не старше 5 минут), иначе админка предложит
  «Войти заново»;
- выдать или снять можно только роль, все права которой есть у самого меняющего (иначе 403, в ответе названы недостающие
  права): тот, у кого есть `users.roles.manage`, но нет `roles.manage`, не выдаст `admin` и не заберёт его у админа.
  Тот, у кого есть `roles.manage`, не ограничен — он и так определяет любую роль. В приложении сервиса права — из токена
  (активный режим), в другом приложении — по ролям в нём (у админа проекта с `roles.manage` в токене — любые);
- повторное действие без изменений записи в журнале не оставляет.

## Админка

`/admin/` у сервиса входа проекта:

| Раздел | Что |
|---|---|
| Обзор | права проекта и приложений под вашим управлением |
| Пользователи | поиск, карточка: блокировка, роли по приложениям, доступ к приложениям, сессии, сброс пароля и 2FA, способы входа |
| Журнал | действия сотрудников и входы (30 дней) |
| Приложения → пользователи, роли, журнал | управление ролями и правами одного приложения |
| Вход и коды | способы входа проекта, коды, расход ([login-methods.md](login-methods.md)) |
| Оформление | название, логотип, цвета ([account-and-branding.md](account-and-branding.md)) |
| Сервисы | ключи сервисов проекта |

Консоль Keycloak остаётся техникам; админам проектов её не давать — она про всё.

## Ключи сервисов

У каждого сервиса проекта свой ключ (`client_id` + секрет); по нему он получает токен и ходит в сервис входа и в другие
сервисы проекта. Админ выдаёт ключ и права в разделе «Сервисы». Права бывают двух видов: в сервисе входа
(`service.users.read` — читать человека, `service.access.check` — проверять доступ, `service.catalog.declare` —
объявлять права своего приложения) и в приложениях проекта (`app:право`, например `notifications:notifications.send`).
Перевыпуск бывает срочным (старый секрет перестаёт действовать сразу) и плановым (`keepTokens`: выданные токены
доживают срок); сервис перечитывает секрет из файла без перезапуска. Отзыв гасит выданные токены и удаляет ключ.
Пошагово — [embedding-guide.md](embedding-guide.md).

## API администрирования

Ответы — в `Envelope` с кодами ошибок; право берётся из токена. Основное:

| Метод и путь | Право | Что |
|---|---|---|
| `POST /auth/mode { activeMode }` | вошёл | сменить свой режим (`{ app, activeMode }` — в другом приложении) |
| `GET /auth/admin/users?search&page&pageSize` | `users.view` | люди проекта |
| `GET /auth/admin/users/{id}` | `users.view` | карточка |
| `PUT /auth/admin/users/{id}/restriction { restricted, reason }` | `users.block` | заблокировать / разблокировать |
| `PUT /auth/admin/users/{id}/apps/{clientId}/access { hasAccess }` | `users.block` | открыть / закрыть доступ к приложению |
| `POST /auth/admin/users/{id}/logout` | `users.sessions.manage` | «выйти везде» |
| `POST /auth/admin/users/{id}/password-reset` | `users.credentials.manage` | письмо со ссылкой на смену пароля |
| `DELETE /auth/admin/users/{id}/two-factor` | `users.credentials.manage` | убрать 2FA (после недавнего входа) |
| `GET/POST /auth/admin/apps/{clientId}/permissions` | `roles.manage` | права приложения |
| `GET/POST/PUT/DELETE /auth/admin/apps/{clientId}/roles` | `roles.manage` | роли приложения и их состав |
| `GET /auth/admin/apps/{clientId}/users` | `users.roles.manage` | люди приложения |
| `PUT /auth/admin/apps/{clientId}/users/{id}/roles { roles }` | `users.roles.manage` | выданные роли (ровно этот список) |
| `GET /auth/admin/audit`, `GET /auth/admin/login-events` | `audit.view` | журнал действий и входов |
| `GET/PUT /auth/admin/branding` | `branding.manage` | оформление проекта |
| `GET/PUT /auth/admin/codes/settings`, `/sign-in/methods` | `sign-in.manage` | коды и способы входа |
| `GET /auth/admin/services` и далее | `services.manage` | ключи сервисов |

Правила имён: право — с точкой (`orders.export`), роль — строчная латиница, цифры, дефис (`support`). Встроенные роли
удалить нельзя; у `admin` нельзя убрать `roles.manage`.

Для сервисов по ключу: `GET /auth/services/users/{id}`, `GET /auth/services/users?login=…`,
`GET /auth/services/users/{id}/access?permission=…`, `PUT /auth/services/catalog`.

Свои сессии человека: `GET /security/sessions`, `POST /security/sessions/{id}/terminate`,
`POST /security/sessions/terminate-all-others`, `GET /security/logins`.
